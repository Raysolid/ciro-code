在 Ciro Code 中：
- **模式 (Mode)** 决定了：**此刻 Agent 的行为准则与工具有哪些权限？**
- **模型 (Model)** 决定了：**由哪颗大语言模型提供推理能力？**（在工作台设置中独立自由切换）

---

## 四档模式权责对照

| 模式 | 目标场景 | 允许工具与权限 | 人工把关点 |
|------|----------|----------------|------------|
| **Ask** | 摸清架构、探索代码、查阅文档 | **严格只读**<br>仅开放 `read_file`、`list_files`、`grep` 等读取检索工具 | 绝不写入文件，完全零风险 |
| **Plan** | 复杂重构、架构设计、方案预审 | **方案规划导向**<br>可检索代码并生成多阶段实施方案与拟改动清单 | 需用户审阅并批准技术方案后才进入实施 |
| **Agent** | 编码实现、日常重构、单测闭环 | **全功能受控执行**<br>在策略沙箱内写文件、执行 Shell 测试命令 | 敏感命令与边界外文件弹窗人工审批 |
| **Debug** | 解决报错、排查单测失败、修复缺陷 | **假设驱动诊断**<br>重点读取报错日志并提出针对性最小改动补丁 | 控制改动影响面，快速恢复测试绿灯 |

---

## 推荐工程工作流：四模式流转流水线

对于复杂的功能开发或重构，推荐采用标准生命周期流水线：

```text
[1. Ask] 探索上下文  ──>  [2. Plan] 制定方案与 Diff 清单  ──>  [3. Agent] 受控执行与测试  ──>  [4. Debug] 针对性修偏
```

1. **第 1 步：Ask 摸清现状**  
   先以只读方式向 Ciro 询问现有逻辑、依赖结构与潜在影响面，避免 Agent 在不理解全貌时盲目修改。
2. **第 2 步：Plan 谋定后动**  
   要求 Ciro 产出分步骤的重构计划与涉及文件清单。由你审查方案是否符合团队设计规范。
3. **第 3 步：Agent 受控执行**  
   确认方案后切至 Agent 模式，让其按照计划修改代码并运行单元测试。在 Changes 面板核对实时 Diff。
4. **第 4 步：Debug 最小修偏**  
   若测试遇到偶发报错，切到 Debug 模式，提供报错栈并指令 Ciro 生成最小修复补丁。

## 如何切换模式

- **在工作台界面**：直接点击顶部导航栏中的模式标签（Ask / Plan / Agent / Debug），即时无缝切换。
- **命令行初始指定**：
  ```bash
  ciro web --mode ask      # 以只读模式启动
  ciro web --mode agent    # 以受控执行模式启动
  ```
- **工作区默认配置**：在 `.ciro/config.yaml` 中设置 `mode: ask` 锁定团队默认模式。
