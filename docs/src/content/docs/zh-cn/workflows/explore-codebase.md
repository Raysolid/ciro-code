---
title: 探索代码库
description: 用 Ask 模式只读摸清陌生代码库、架构分层与核心依赖。
---

接触陌生仓库或梳理跨模块调用时，不宜一上来就改代码。**Ask 模式**把 Kernel 限制在只读沙箱，分析过程不写文件。

---

## 快速起步

1. 在仓库根目录以只读模式启动：
   ```bash
   ciro web -w . --mode ask
   # 或终端：ciro --mode ask
   ```
2. 确认顶栏为 **Ask**（可用 `Shift + Tab` 切换）。

---

## 提示词模板

目标与边界写清楚，结论更稳。可直接复制改写：

### 场景 1：技术栈与入口

```text
请阅读项目的根构建配置（如 package.json / pom.xml）和主要入口文件，总结技术栈、模块分层，以及本地构建与测试命令。
```

### 场景 2：垂直链路追踪

```text
我想理清用户从登录到拿到 JWT 的流程。请从 @src/controllers/auth.ts 出发，顺着 Service / Mapper 检索并阅读相关代码，画出调用链路。
```

### 场景 3：评估改动影响面

```text
如果我要修改 @src/types/user.ts 中的 UserRole 枚举，当前仓库里哪些模块和测试会受影响？请列出受影响文件与主要风险点。
```

---

## 人工核对

- **工具流**：应以 `grep`、`list_files`、`read` 为主（按需可有只读 `bash` / `WebFetch`）；
- **无写入**：右侧 **Changes** 应始终为空；
- **收窄范围**：若模型扫到无关目录（如 `.git`、构建产物），按 `Esc` 中断并补充路径约束。

---

## 常见误区

- ❌ **在 Ask 下要求改代码**：只读策略会拒绝写入，白耗一轮；
- ❌ **整文件粘贴进对话**：用 `@路径` 让 Kernel 按需读取，避免撑爆上下文。
